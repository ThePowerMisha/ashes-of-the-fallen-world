# Сервер и правила
- Java 17, Forge из manifest.json, одинаковые обязательные моды на сервере и клиентах. На сервере уберите только точно клиентские моды после проверки их зависимостей; список кандидатов в overrides/ashes_docs/CLIENT_ONLY.txt. Не копируйте клиентский options.txt на сервер.
- Перенесите config, defaultconfigs (если имеются) и kubejs из профиля в корень сервера. Создайте новый тестовый мир. Не включайте offline-mode и не отключайте проверку подлинности.
- Примените server.properties.example как шаблон (не перезаписывайте действующие настройки без резервной копии). Рекомендуются PvP off, normal, view-distance 10, simulation-distance 6, белый список.
- 10–16 ГБ для выделенного сервера на 4–6 человек — ориентир, а не гарантия.
- Сделайте одну команду FTB Teams для общего сюжета. Проверяйте разделение наград и доступов. Используйте FTB Chunks и согласованные правила доступа.
- Sculk Horde: после первого запуска найдите сгенерированный конфиг мода. В ветке 1.20 исходника ModConfig.java предусмотрены trigger_ancient_node_automatically (false), disable_defeating_sculk_horde (false), infection_speed_multiplier, purification_speed_multiplier и sculk_raid_global_cooldown_between_raids_minutes. Проверьте точные имена и расположение в установленной версии. Для среднего режима начните с автоматического пробуждения false, скорости заражения 0.5 и очищения 1.0; после пробного мира настройте. Не отключайте загрузку чанков вслепую: это ломает часть штатных механик орды. Защита базы от распространения и пауза на пустом сервере пока не реализованы.
- Пробуждение только после согласия участников и резервной копии. Квест не блокирует штатную активацию технически. Остановленный сервер не симулирует мир; для паузы пустого сервера потребуется отдельная настройка хоста или мод.
- Не обновляйте версии автоматически. Перед каждым обновлением копируйте мир, config и данные FTB Quests.
